# Redmine Kanban Worktime機能 UI変更仕様書

## 1. 目的

`redmine_kanban/add-worktime` のWorktime機能について、操作フロー・TimerSessionの安全性を維持しつつ、**Worktime関連UIを今回提示された画像のデザインへ統一する**。

今回の画像をWorktime UIの**デザイン正本**とする。

対象となる主要UIは以下の3種類。

1. タイマー開始ダイアログ
2. タイマー実行中のGlobal Timer
3. 作業時間未登録時のGlobal Timer

画像に示されていない復旧・管理系ダイアログについては、同じデザイントークンを適用し、Worktime全体として統一感を持たせる。

# 3. UI実装の基本方針

今回提示された画像を基準として、Worktime UIを以下の方向へ統一する。

- 大きめの角丸
- pill型ボタン
- 必要最小限の情報
- 状態が色だけでなくアイコン・文言でも判別できる
- runningはdark theme
- pendingはwarm warning theme
- start dialogは白背景
- 主要操作を右側へ配置
- 時刻は視認しやすく強調
- Worktimeだけで完結した一貫したデザイン体系を持つ

既存Kanban一般UIへ無理に合わせるより、**提示画像のWorktimeデザインを優先する**。

# 39. StopとrecordingAttemptの競合対策

前回レビューで確認された競合対策を今回の変更に含める。

Stop時に、

```text
stop
```

と、

```text
beginRecording
```

を別mutationで実行しない。

同じ排他的mutation内で処理する。

これにより複数タブが同一recordingAttemptを自分のものとして扱う問題を防止する。

---

# 40. Canvas GanttとのTimerSession互換性

UIは今回の画像へ変更するが、Canvas GanttとのTimerSession共有仕様は維持する。

```text
same Redmine instance
+
same current user
=
one TimerSession
```

とする。

したがって、

```text
Canvas GanttでStart
↓
KanbanでRunning表示
```

も正常に動作すること。

逆方向も同様。

---

# 41. Mutation Lock

Canvas GanttとKanbanで共有するTimerSessionについて、fallback lockを完全互換にする。

一致させるもの：

- Web Locks
- IndexedDB
- localStorage fallback
- lock key
- DB
- store
- lock data format
- transaction boundary

UI変更によってこの修正を外さない。

# 44. Time Entry成功判定

成功判定はallow-list方式とする。

以下は成功として扱ってよい。

```text

```

以下は成功扱いしない。

```text

/error
想定外ページ
他プラグイン画面
```

結果不明時は`unknown`へ移行する。

## 52. 実装判断ルール

```text

```

を確認し、既存アーキテクチャへ適切に適用する。

ただし、Worktime UIの外観については独自解釈で変更せず、**今回提示された3枚の画像を最終的な表示基準とする。**

優先順位：

```text
1. 二重登録・データ破損防止
2. TimerSession整合性
3. 提示画像とのUI一致
4. Worktime操作フロー
```
